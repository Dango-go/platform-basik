│       └── endpoints/
│           ├── __init__.py

│   ├── version.py                # DatabaseVersionEntity (версії БД, Helm Chart URL, CRD mapping)
│   ├── preset.py                 # ResourcePresetEntity (Small/Medium/Large: CPU, RAM, Storage)
│   └── schema.py                 # ConfigSchemaEntity (JSON Schema конфігураційних параметрів)
│
├── seeders/                      # Початкове заповнення даними (Seed Data)
│   ├── __init__.py
│   └── initial_catalog.py        # Автоматичний скрипт наповнення каталогу (Postgres, Redis, ClickHouse) при першому старті
│
└── services/                     # Бізнес-логіка модуля
    ├── __init__.py
    │
    └── catalog_manager/          # 👈 ОСНОВНИЙ МОДУЛЬ УПРАВЛІННЯ КАТАЛОГОМ
        ├── __init__.py           # Публічний експорт модуля
        ├── service.py            # Головний оркестратор каталогу (CatalogService Facade)
        ├── repository.py         # Запити до БД (CRUD для типів БД, версій та пресетів)
        ├── preset_manager.py     # Логіка тарифних сіток (Small / Medium / Large / Custom)
        ├── schema_generator.py   # Генератор JSON Schema для динамічних форм фронтенду

1. КРОК 1: Фронтенд робить GET /api/v1/catalog
   └─► Каталог повертає JSON: ["PostgreSQL (іконка)", "Redis (іконка)", "ClickHouse (іконка)"]
   └─► Фронтенд малює 3 красиві картки з кнопками.

2. КРОК 2: Користувач клікнув на "PostgreSQL"
   └─► Фронтенд робить GET /api/v1/catalog/postgresql/presets
   └─► Каталог повертає JSON: 
       • Small (1 CPU, 2GB RAM) 
       • Medium (2 CPU, 8GB RAM) 
       • Large (4 CPU, 16GB RAM)
   └─► Фронтенд малює тарифні картки.

3. КРОК 3: Користувач хоче змінити тонкі налаштування (max_connections, порт)
   └─► Фронтенд робить GET /api/v1/catalog/postgresql/schema
   └─► Каталог повертає JSON-схему: {"max_connections": "number", "enable_backups": "boolean"}
   └─► Фронтенд автоматично малює поле вводу та ползунок/гачок.
